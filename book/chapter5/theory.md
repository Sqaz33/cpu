# Аппаратно-программный интерфейс

## Драйвер устройств

*Драйвера устройств* предоставляют программным приложениям стандарт. интерфейс для взаимодействия с переф. устр.

На низком уровне, драйвер управляет ресурсами и обменном данных между процом и устройством.

Драйверы, которые выполняются с повышенными привелегиями, называются *драйверами режима ядра*. *Ядро* - элемент ОС, служащий инт. между аппаратными средствами компьютера и функциями ос более высок. ур., такими как планировщик.

## Параллельный порт

Порт для принтеров. Прогр. инт. состоит из 3х 8-разр. рег, привязанных к послед. номерам портов, начиная с 0x378.

Чтение в драйверах (привелег. режим):

```x86asm
mov edx, 0x378
in al, dx
```

```cpp
char input_byte;
input_byte = inb(0x378);
```

Запись (привелег. режим):

```x86asm
mov edx, 0x378
movzx eax, BYTE PTR [rsp+0x7]
out dx, al
```

```cpp
char output_byte = 0xA5;
outb(output_byte, 0x378)
```

## Драйвера устройств PCIe

Системы PCIe сами решают задачи по последовательной передачи данных, переводя в них инструкции in, out

Устройства PCIe автоматически настраиваются и становятся доступными ОС.

Инт. обмена данных между проц. и PCIe устр. может включать любую комбинацию из след.:

* один или несколько диап. портов io
* одна или несколько областей адр. - расп по памяти
* подключение к обаботчику прерываний процессора

## Структура драйверов устройств

*Драйвер устройтсва* - программный модуль, реализ. набор предопред. ф-ций, позволяющих ОС связывать драйвер с переферийными устройствами и осущ. доступ к этим устр. Это дает возм. системным процессам и пользовательским прилож. выполнять ф-ции io на совместно исп. устр.

## Базовая система ввода-вывода (BIOS)

В совр. ПК используется для тестирования системы и настройки перефирийных устройств. Затем проц. взаимодействует с переферийными устройствами напрямую, без BIOS`а.

Одно из первых действий системы после запуска под управлением BIOS - *самотестирование при включении  питания (power-on self-test, POST)*. Во время которого BIOS пытается взаимодействовать с перефирией.

BIOS может настраивать PCIe устр. После настройки у PCIe устр. - диап адресов, портов и номера прерываний.

## Unified Extensible Firmware Inteface (UEFI)

Единый расширяемый интерфейс встроенного ПО.

Улучшенный BIOS с новыми функциями и быстрой инициализацией системы.

## Процесс загрузки ОС

Цель - запусть систему после включения и иниц. ОС, оставив компьютер в известном состоянии и готовым к выполн. работы.

Каждое запоминающее устр. содержит информацию о своих разделах. Каждый раздел имеет файловую систему. Современные зап. устр. имеет формат разделов GPT (GUID Partition Table) (Global Unique IDentifier, GUID). Накопитель с разметкой GPT имеет максимальный размер 2^64 * 512(байтовых секторов) и поддержиывает до 128 разделов.

## Загрузка c BIOS

BIOS после POST и настройи PCIe иниц. процесс загрузки. Предпринимает попытку загрузки с первого устройства в списке приор. Считывает из загр. сектора MBR исп. код, называемый *загрузчиком* и передает ему управление. На этом исполнение BIOS заканчивается.

## Загрузка с UEFI

После POST и настройи PCIe иниц. процесс загрузки. UEFI считывает код диспетчера загрузки и файлы загрузчиква из заданных расположений на системном диске, заданные в *данных конфигурации загрузки (boot configuration data, BCD)*. Затем выполняет эти файлы в процессе запуска.

## Доверенная загрузка

Загрузка с проверкой кода с помощью хеш-функции и сверки со значением идущим с кодом. Это значение шифруется поставщиком при помощи закрытого ключа. Затем загрузочное ПО расшифровывает этот ключ с помощью открытого ключа, который хранится в аппартаном копоненте *доверенном платформенном модуле (trusted platform module, TPM)*

## Операционные системы

*ОС* - многуровневый пакет ПО, обеспеч. создание среды, в которой исполняются приложения. Приложение исп. под упр ОС выполняют алгоритмы, реализованные в виде последовательности инструкций процессора, и по необходимости обмениваются данными с периферийынми устр. с помощью опер. ввода-вывода.

Операционная система предоставляет стандартные интерфейсы для доступа приложений к системным ресурсам: процессорному времени, файлам, а также устройствам ввода и вывода.

Категории ОС:

* RTOS - минимальное время отклика на вход
* ОС не реального времени - нет гарантии на минимальное время отклика.

После запуска ядра ОС, оно настраивает:

* процессор (регистр и связанные устройства ввода-вывд, чипсет)
* настройка MMU
* запуск планировщика и процесса простоя
* составление перечня устройс и их привязка с периферйному устр.
* настройка прерыв. и их запуск.
* запуск системных сервисов (сетевой стек, веб-сервер)
* пользовательский интерфейс

## Процессы и потоки

*Поток* - последовательность программных инструкций, которые выпол. изолированно от других потоков.

*Планировщик* - управляемые прерыв. процедура, выполняется в период. интервалы времени, а также в ответ на действия потоков. Во время иниц. ОС к обработчику прерыв. планировщика подключается период. таймер и запускается таймер план.

Во время иниц. процесса, ядро добавляет в свой список *блок управления процессом (process control bloc, PCB)*, структуру, содерж. информацию для взаимодействия с ним ОС: выдел. память, файл кода и т.д.

Каждому процессу даетя уникальный номер *process id, PID*

У каждого потока есть TID

Планировщик хранит инф о потоке в *блоке упр. потока (thread control block, TCB)*, у каждого процесса есть список TCB. TCB хранит *контекст процессора* - набор данных для выполнения потока: регистры процессора, указатель стека, регистр флагов, указатель инструкций и т.д.

Категории алгоритмов планирования вып. потоков.:

* Невытесняющие алгоритмы - поток сам контролирует время своего выполнения
* Вытесняющие алгоритмы - планировщик может остановить поток в любой момент

## Алгоритмы планирования и приоритеты процесса

Можно выставить приоритет процессам.

Алгоритмы:

* Первый пришел, первым обслужен - невытесняющий, без учета приоритета.
* Кооперативная многопоточность - невытесняющий, с учетом приоритета.
* Циклическое планирование - вытесняющий, с равными приоритетами. Идет по заколц. списку.
* Планирование с вытесмнением и фиксированным приоритетом - вытесняющий, с учетом приоритета. Когда поток с более высоким приор. переходит в режим ожид. он заменяет текущий.
* Частотно-монотонное планирование (rate-monotonic scheduling, RMS) - вытесняющий, с учетом приоритета. Жесткие сроки.
* Справедливое планирование - вытесняющий, с учетом приоритета. Чем больше пото потребляет процессорного времени, тем меньше у него приоритет. (linux)
* Многоуровневая очередь с обратной связью. - из книги - то же самое что и справед. (windows)
